# mogameserver 개발 계획

[저장소 처음으로](../README.md) · [교재 학습 안내](LEARNING_GUIDE.md) · [IOCP 단계별 안내](IOCP_GUIDE.md)

`mogameserver`는 교재 실습과 IOCP 서버 개발에서 배운 내용을 재사용 가능한 게임 서버 라이브러리로 발전시키려는 목표입니다. 학습 코드를 읽으며 공통으로 제공할 기능과 응용 프로그램이 담당할 기능의 경계를 정리합니다.

## 현재 위치

현재 저장소의 C++ 프로젝트는 모두 실행 프로그램 형식이며, 독립된 `mogameserver` 라이브러리 프로젝트는 없습니다. 라이브러리 설계의 출발점은 [IOCP 단계별 코드](IOCP_GUIDE.md)에 있는 `IOCPServer`, `ClientInfo`, 접속 및 송수신 콜백입니다.

Lv8에는 `PacketManager`, 사용자 관리와 로그인 코드가 있고, Lv9에는 Redis 연동 작업이 추가되어 있습니다. 공통 네트워크 기능과 응용 기능의 경계를 살펴보기에 좋은 비교 대상입니다.

## 라이브러리의 책임 초안

| 공통 네트워크 기능 후보 | 응용 프로그램에서 담당할 기능 후보 |
| --- | --- |
| 소켓과 IOCP의 시작 및 종료 | 서버별 로그인 규칙 |
| 연결 식별과 접속 및 종료 통지 | 사용자와 채팅방의 의미 및 상태 |
| 비동기 송수신과 완료 통지 | 게임 규칙과 플레이어 처리 |
| 작업 중인 버퍼와 연결 자원의 수명 관리 | Redis의 키 구조와 저장할 데이터 |
| 수신 데이터를 응용에 전달하는 인터페이스 | 응용별 패킷 ID와 요청 처리 |

공통 패킷 규격과 직렬화까지 라이브러리에 포함할지는 별도 설계 항목입니다. 처음부터 모든 응용 기능을 공통화하기보다, 에코 서버를 구성하는 데 필요한 경계를 먼저 설명할 수 있도록 합니다.

## 문서로 먼저 정리할 항목

- [ ] 라이브러리가 지원할 운영체제, I/O 모델과 사용 범위를 적기
- [ ] IOCP 단계별로 바뀐 이유와 남아 있는 의문 기록하기
- [ ] 초기화, 접속, 수신, 송신, 종료에서 호출되는 순서 정리하기
- [ ] 연결 객체와 송수신 버퍼의 소유권 및 수명 정리하기
- [ ] 응용에 공개할 함수와 콜백의 역할 초안 작성하기
- [ ] 빌드 및 실행을 확인한 기준 단계와 확인 결과 기록하기

## 향후 구현 단계

아래 항목은 각 단계의 학습 코드를 보존하면서 진행할 개발 목표입니다. 라이브러리 분리와 코드 변경은 이후 구현 작업에서 다룹니다.

| 순서 | 개발 목표 | 완료 기준 |
| --- | --- | --- |
| 1 | 에코 통신을 기준으로 사용할 IOCP 단계 선정 | 사용한 구성과 클라이언트, 통신 및 종료 결과가 기록됨 |
| 2 | 공통 네트워크 기능을 독립 라이브러리로 구성 | 별도 에코 프로그램이 라이브러리를 참조해 동작함 |
| 3 | 연결과 비동기 데이터 수명 검증 | 여러 클라이언트, 연결 종료, 송수신 도중 오류, 서버 종료 시 동작을 확인함 |
| 4 | 패킷 처리 경계 검증 | 나뉘어 들어온 패킷과 여러 패킷이 합쳐져 들어온 경우를 확인함 |
| 5 | 채팅 또는 간단한 게임 예제에 적용 | 응용 기능이 공개 인터페이스를 통해 네트워크 기능을 사용함 |

교재의 한 챕터를 마칠 때마다 [학습 기록 항목](LEARNING_GUIDE.md)을 채우고, 그중 라이브러리 설계에 영향을 주는 결정을 이 계획에 이어서 기록합니다.
